# Acceptance Test — Process Certificate Foundation and Native Stock Ledger Filter

## Scope

This test accepts the configuration and ERPNext inventory-dimension foundation only. It does not
accept scanner-driven issuance or process-gate enforcement, which belong to the next package.

Record the deployed Git revision and tester evidence before marking this package accepted.

## Sample records

| Record | Sample |
|---|---|
| Item | `PLS_ABC` |
| Certificate Type 1 | `SANITISED` — Sanitised |
| Certificate Type 2 | `PRINTED` — Expiry/Serial Printed |
| Certificate Set 1 | `SANITISED` |
| Certificate Set 2 | `SANITISED + PRINTED` |
| Source Warehouse | existing raw-material Warehouse |
| Target Warehouse | existing WIP or finished Warehouse |

## 1. Deployment checks

1. Run the normal site migration and build sequence.
2. Open **Inventory Dimension** in ERPNext.
3. Confirm one row named **Process Certificate Set** exists.
4. Confirm its Reference Document is **CFG Process Certificate Set**.
5. Confirm **Apply to All Inventory Documents** and **Validate Negative Stock** are enabled.
6. Confirm there is no duplicate dimension after a second migration.

Expected: migration is idempotent and the same dimension remains.

## 2. Create approved certificate types

1. Open **CFG Kanban > Process Certificate Types**.
2. Create `SANITISED`, name `Sanitised`, revision `1`, Active enabled, and a controlled
   description. Submit it.
3. Create and submit `PRINTED`, name `Expiry and Serial Printed`, revision `1`.
4. Negative test: attempt to approve an inactive type.
5. Negative test: enter both Restricted to Item and Restricted to Item Group.

Expected: approved active types save; both negative tests are rejected clearly.

## 3. Create immutable certificate sets

1. Open **Process Certificate Sets**.
2. Create one set containing `SANITISED`. Leave Set Code and Set Name blank initially.
3. Confirm a stable `PCS-...` code and readable `SANITISED` name are generated.
4. Create another set containing `SANITISED` and `PRINTED`.
5. Confirm its readable name is `PRINTED + SANITISED` or the same codes in deterministic sorted
   order.
6. Attempt to create the same combination again.
7. Attempt to edit membership of a saved set.
8. Disable a set without a Deactivation Reason, then with a reason.

Expected: duplicate/membership edits and unexplained deactivation are rejected. Historical sets are
not deleted.

## 4. Verify Production Master configuration validation

1. Open a small Production **CFG Kanban Master** with at least one Operation Profile.
2. Add an Input Certificate Requirement for the second operation:
   - Required Certificate: `SANITISED`
   - Gate Stage: `Before Operation Start`
   - Requirement Group: `DEFAULT`
   - Group Logic: `All Required`
   - Minimum Revision: `1`
3. Add an Output Certificate Rule to the first operation:
   - Certificate Type: `SANITISED`
   - Output Action: `Issue`
   - Apply To: `Processed Tagged Quantity`
4. Save.
5. Negative test an operation outside the Master route.
6. Negative test an inactive/draft Certificate Type.
7. Negative test inconsistent All/Any logic inside the same group.

Expected: valid rules save and every negative configuration is rejected.

## 5. Verify native ERPNext document fields

1. Open a new **Stock Entry** and select a stock movement purpose suitable for the test site.
2. Add an Item row.
3. Confirm the row exposes **Process Certificate Set**. For a transfer, confirm ERPNext also
   exposes the correct source/target dimension fields generated by Inventory Dimension.
4. Check another native stock document used by the site, such as Purchase Receipt or Delivery Note.

Expected: the dimension is available on ERPNext's supported inventory transaction rows without CFG
Kanban replacing the native ERP form. A Work Order or Job Card itself does not post Stock Ledger;
its resulting Stock Entry carries the dimension.

Do not use Stock Reconciliation for this acceptance test unless the deployed ERPNext revision has
been independently verified to support Inventory Dimensions there.

## 6. Post a safe quantity-conserving test

Use a test Item/Warehouse and follow the site's ERP stock policy.

1. Record the starting stock balance.
2. Create the site's accepted same-Item Repack/state-change transaction.
3. On the outgoing row, select the old certificate state (blank for initial stock).
4. On the incoming row, select `SANITISED`.
5. Keep Item, Batch, UOM, and total quantity conserved.
6. Submit.

Expected: total Item stock is unchanged, while the inventory dimension balance moves to the new
exact certificate set.

## 7. Verify native Stock Ledger filtering

1. Open **Stock Ledger** from the CFG Kanban workspace or ERPNext Stock reports.
2. Filter Item = `PLS_ABC`.
3. Filter **Process Certificate Set** = the `SANITISED` set.
4. Confirm only submitted entries carrying that exact set appear.
5. Open **Stock Balance** and repeat the exact-set filter.
6. Clear the filter and confirm ordinary total Item balance remains visible.

Expected: native reports filter certificate-qualified stock even though the transaction was created
directly in ERPNext.

## 8. Negative stock-dimension test

Attempt, in a safe test environment, to issue more `SANITISED` stock than exists in that exact
dimension while unqualified Item stock still exists.

Expected: ERPNext rejects the transaction because negative stock validation is dimension-aware.

- Stock Ledger exact-set filter screenshot;

## Acceptance boundary

Passing this document does not prove scanner-only floor issuance, automatic certificate inheritance,
revocation, process gates, or genealogy. Do not enable those production behaviours until the runtime
package and its kiosk/full-screen acceptance test pass.
